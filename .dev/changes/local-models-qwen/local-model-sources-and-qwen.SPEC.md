# 本地模型：下载源、模型目录与 Qwen3-ASR 内置

## 问题

本 fork 的本地转写只内置 Whisper（whisper.cpp / whisper-rs），而模型的获取与存放有三个现实障碍：

1. **下载源写死 HuggingFace**。本机实测 `huggingface.co` 直连超时；现有出路只有手工设 `HTTP_PROXY/HTTPS_PROXY` 环境变量，而 GUI 启动的应用默认拿不到这些变量（用户级/机器级均未设置）。
2. **模型目录固定**在 `%APPDATA%\com.voquill.desktop\transcription-models`，无法换盘；7 个 Whisper 模型全量约 7.5 GB。
3. **内置模型只有 Whisper**。Qwen3-ASR-0.6B 在同类工具（hex）上表现好且快，但它需要另一套 GGUF 推理实现，当前架构没有入口。

同时记录一个与"快"直接相关的事实：本机 `rust-transcription-gpu-*.exe` 与 `rust-transcription-cpu-*.exe` **字节完全相同**（sha256 一致）。原因是构建时 `VULKAN_SDK` 未设置，`apps/desktop/scripts/prepare-sidecars.mjs` 用 CPU 二进制镜像成 GPU 版本；而该二进制不含 `gpu` 特性，启动时 `ensure_gpu_runtime_available()` 直接报错，所以本地转写当前只跑 CPU。hex 的"快"有相当一部分来自它发货了 Vulkan 构建。此项不是代码改动，见「开放问题 1」。

## 目标与预期

### Solved（完成即达成）

1. 设置里可以选择下载源顺序：**镜像优先（默认）/ 官方优先**。下载按序尝试候选源，任一源成功即完成，不需要用户设置环境变量。
2. 设置里可以把**模型目录**改到任意路径（如 D 盘），重启后仍生效；默认路径保持现状。
3. 设置 → AI 转写 → Local 里出现内置模型 **`Qwen3-ASR 0.6B`**；下载、选中、录一段中文能出正确文本，全程走本地 sidecar，不依赖外部服务。
4. **本地模型统一使用独立显卡**：有独显的机器上，Whisper 与 Qwen 都跑在独显上；不存在"Qwen 用显卡、Whisper 用 CPU"的混合状态。为此 Whisper 的显卡版本必须真实构建出来，不允许再用 CPU 版本顶替。
4. **Whisper 本地路径行为不变**：同一模型、同一段音频，转写结果与改动前一致；设备选择、胶囊阶段、历史、注入、字典流程不变。

### 性能基线（本机实测，作为 Good 的参照）

GTX 1050 Ti + Qwen3-ASR-0.6B Q8_0：8 秒录音约 0.66 秒、30 秒约 1.9 秒、135 秒约 7.1 秒（12–19× 实时）；纯 CPU（i5-8400）为 3.5–6.3× 实时。以上不含 sidecar 冷启动装载。

### Good（用户第一眼会看什么）

- 中文与中英混说的准确率相对 whisper large-v3-turbo 的差异（用 `%APPDATA%\com.voquill.desktop\transcription-audio` 里的真实录音对比）。
- 字典词是否被"念"进转写文本（Qwen3-ASR 0.6B 的已知倾向，其官方文档点名它比 1.7B 更容易出现）。
- 设置页只多出"下载源""模型目录"两项和一个模型条目，没有多余开关。

### Verified（谁验证什么）

Agent 负责（客观、可复现）：

- 无 `HTTP_PROXY/HTTPS_PROXY` 的干净环境下从镜像完成 Qwen 850 MB 下载，落盘字节数等于登记值。
- 候选源全部指向无效地址时必须报错，不得出现"已下载"状态。
- 真机端到端：下载 → 选中 → 录音 → History 出现文本、音频落盘、胶囊阶段正常。
- 换回 whisper large-v3-turbo 跑同一段音频，输出与改动前一致。
- `packages/rust_transcription` 测试与项目 `check-types`/`lint` 通过。

用户负责（不可代劳）：

- 在自己录音上判断 Qwen 的质量是否值得长期使用。
- 判断"松键后整段出字、没有边说边出字"这一体验差异是否可接受。

## 行为约定

### 下载源

- 候选源由 Rust 侧模型注册表提供，顺序由设置项决定：
  - 镜像优先：`hf-mirror.com` → `huggingface.co`
  - 官方优先：`huggingface.co` → `hf-mirror.com`
- 单个源的成功条件是：HTTP 2xx **且**落盘字节数等于登记值。不满足则删除临时文件并尝试下一个源；全部失败返回最后一个错误。
- `RUST_TRANSCRIPTION_MODEL_URL_<SLUG>` 仍为最高硬覆盖：设了它就只用它，不参与排序。
- 现有"失败即删除临时文件、不保留半成品"的行为不变；本变更不做断点续传。
- **单次尝试必须有连接超时与读取超时**，否则被阻断的源会永久挂住、回退永不触发。超时按"远端失败"处理，切下一个源。
- **切源发生在同一个下载任务内**：前一个源失败时不得先发布 `Failed`（前端会停止轮询）；只有全部源失败才终结任务。已下载字节数可回退，进度按当前尝试重新计算。
- **只有远端失败才切源**（连接、HTTP 状态、流中断、字节数不符）。本地落盘失败（磁盘满、权限、flush/rename 失败）直接失败，不重试，错误信息带源地址。
- **已存在文件的捷径也必须核对登记字节数**：长度不符视为未下载（现有实现把任何非空文件当作已完成）。
- **模型管理（下载、删除、状态查询）统一由同一个 sidecar（CPU 侧车）承担**，避免 CPU/GPU 两个进程各自持有下载注册表却写同一目录。

### 模型目录

- 默认值不变：`appDataDir()/transcription-models`。
- 设置项保存绝对路径；空值表示使用默认。
- 切换目录由 sidecar facade 统一处理：同时重置 CPU 与 GPU 两个实例，清空 `modelsDirPromise` 与已就绪缓存，并等待正在进行的启动；只调用现有 `resetRuntime()` 不足。
- **下载、删除或转写进行中不允许切换目录**，界面给出提示，不杀进程（否则会遗留 `.download` 与未完成的下载任务）。
- 切换后**旧目录中的模型不迁移、不删除**，由用户自行处理；新目录为空时模型显示为未下载。

### Qwen3-ASR 0.6B 内置条目

| 项 | 值 |
|---|---|
| 模型标识 | `qwen3-asr-0.6b` |
| 文件 | `Qwen3-ASR-0.6B-Q8_0.gguf` |
| 期望字节数 | `850423456` |
| 来源 | `handy-computer/Qwen3-ASR-0.6B-gguf`，revision `e4e16599b900eb0cb36e524514756bb92eb092b7`（与 hex 采用的产物一致；上游权重为 `Qwen/Qwen3-ASR-0.6B` @ `5eb1441`，Apache-2.0） |
| 输入契约 | 16 kHz 单声道 PCM；现有 60 秒分段不变（模型单次上限约 87 分钟，超限报错而非截断） |
| 语言 | 自动识别 30 种；应用传语言提示，`auto` 时不传 |
| 不支持 | 流式、时间戳、翻译 |

### 推理参数映射

- 字典与提示词**只通过现有 `initialPrompt`** 传给模型 context prompt，与 Whisper 当前行为一致；**不使用** transcribe.cpp 的 `vocabulary` 字段（那需要新增一条"字典 → sidecar"的数据通路，本次不做）。
- 当前语言设置 → 语言提示；`auto` 时不传。
- 不建立参数翻译层或统一 prompt 抽象。

### 局部模型的进程保持

- 选择本地模型时，sidecar 不得因为空闲销毁而让每次口述都重新装载模型（本机实测 Qwen 在 GPU 上装载约 3.4 秒）。
- 最小实现：本地模式下不按 60 秒空闲销毁；如需销毁，必须在下次口述前完成预热，使松键后的等待不包含装载成本。
- 该约束同样适用于现有 Whisper 本地模型（其装载同样发生在进程启动后）。

### 设备选择

CPU/GPU 选择沿用现有机制：应用按设备 id 选择 CPU 或 GPU 侧车，侧车把该模式交给推理引擎。Qwen 在 GPU 侧车内用 GPU、CPU 侧车内用 CPU；更细的设备 id（`gpu:0` 与 `gpu:1`）对 Qwen 不生效，这是本变更接受的取舍。

但不得静默：Qwen 的 `inferenceDevice` 必须来自引擎实际报告，界面不得显示"已选 gpu:1"而引擎自选设备却不说明；引擎加载失败与设备不可用必须是两类错误，前者不得被当作"模型未下载"。

**本仓库中的"GPU"特指独立显卡。** 集成显卡（核显）不作为 GPU 选项提供，按 CPU 处理：它不一定比 CPU 快，且当前设备接口只上报名称，无法可靠区分独显与核显。要落实"有独显就默认用独显"，需要 sidecar 额外上报设备类型（独显 / 核显 / CPU），再据此过滤选项并在"用户从未选过设备"时默认选独显（不得覆盖用户已明确选择的 CPU）。

## 架构与质量约束

1. **模型知识的单一来源在 Rust**：文件名、候选 URL、期望字节数、revision 只出现在 `packages/rust_transcription/src/models.rs`。TS 侧只允许出现展示文案（名称、约数大小），不得参与下载或校验决策。
2. **引擎按模型家族隔离**：Qwen 走 transcribe.cpp（GGUF），Whisper 继续走 whisper-rs。不得为统一而迁移现有 Whisper 模型——那会破坏 `hindi2hinglish` 微调模型与现有转写输出。
3. **sidecar 的 HTTP 契约保持稳定**：现有端点与语义不变；新增内容只能是可选参数与新的模型标识。
4. **目录决策留在 TS**：sidecar 只接受 `RUST_TRANSCRIPTION_MODELS_DIR`，不读应用配置、不实现路径规则。
5. **失败必须响亮**：下载失败、模型加载失败、不支持的操作都要返回明确错误；不得静默回落（如镜像失败后改用 CPU 或返回空转写）。
6. **不引入新抽象**：不做源健康度缓存、并发分片、通用模型插件框架、provider 能力矩阵。
7. **不做哈希校验**：以字节数核对代替；sha256 可记入文档但不参与流程判定。
8. **构建前置**：Phase 2 通过 CMake 编译 C/C++ 推理库（与现有 whisper-rs 相同的构建方式）。本机 CMake 由 VS 2022 提供（`G:\Development\Microsoft Visual Studio\2022\Community\...\CMake\bin`，不在默认 PATH）；GPU 路径另需 Vulkan SDK。缺失时按现有逻辑回落 CPU 构建，不得让构建直接失败。

## 验收标准

- 设置中出现"下载源""模型目录"两项并可持久化。
- 干净环境下 Qwen 850 MB 下载完成，文件位于所设目录，字节数为 850423456。
- 所有候选源不可用时界面报错并显示原因。
- 模型目录改到新路径后重启应用，模型状态按新目录显示，旧目录内容未被删除。
- Qwen3-ASR 0.6B 可选、可下载、可删除，并能完成一次中文转写并写入 History。
- Whisper 现有模型仍可下载、校验、转写，输出与改动前一致。
- Qwen 与 Whisper 在音频落盘、历史、胶囊阶段、注入流程上无差异。
- 单源不可达时，在超时后自动切换到下一个源（可用本地不可达地址复现）。
- 两次间隔 5 分钟的口述，第二次松键后不出现 3 秒以上的模型装载等待。
- 下载进行中切换模型目录被拒绝，且不产生残留 `.download` 文件。
- `packages/rust_transcription` 测试、desktop 单测、`check-types`、`lint` 通过。

## 明确不做

- 不把 Whisper 迁移到 transcribe.cpp；不删除 `hindi2hinglish`。
- 不引入 Qwen3-ASR 1.7B、ForcedAligner、QwenCleo；量化档只提供 Q8_0（用户已决定，不再提供 Q4_K_M 等）。
- 不引入 Parakeet/SenseVoice/FunASR 等其他模型家族。
- 不做流式转写、时间戳、翻译。
- 不做断点续传、镜像自动探测、多源并发、下载队列、自动清理旧模型。
- 不做 ModelScope/魔搭上传，不做 GGUF 自行转换。
- 不在本变更内安装 Vulkan SDK（见开放问题 1）。

## 开放问题

1. **魔搭**：transcribe.cpp 需要的融合版 GGUF 目前只存在于 HuggingFace 与 hf-mirror；若希望国内直连不依赖第三方镜像，需要用户自建仓库上传固定文件，不在代码范围内。

已决定（不再是开放问题）：GPU 构建纳入范围，且目标是"有独显就用独显"，覆盖 Whisper 与 Qwen 两条路径；显卡版 sidecar 必须真实构建（见"设备选择"）。验证方式是 CI 构建 + 本机安装实测。
